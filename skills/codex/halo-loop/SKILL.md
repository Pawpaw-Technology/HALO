# HALO Loop

复用 HALO 的诊断、源码核实、最小修改、重跑比较流程。HALO 提供证据线索，Codex 负责核实和实施；模型权重不在本技能的修改范围内。

## 开始与范围

- 先读取当前项目契约和已有工具。使用真实 trace；没有 trace 时先捕获当前已授权任务的记录，不能用模拟数据冒充实际行为。
- “完成任务后改进”先完成业务任务，再运行闭环。显式请求运行闭环时，从现有材料开始；仅要求诊断时停在诊断。
- 默认执行一轮、只验证一个有证据支持的改进假设。用户要求多轮时遵守指定轮数/预算，无收益或前置失败就停止，保留记录。
- 复用原任务授权。闭环本身不新增设备操作、烧录、网络目标、发布或合并权限。

## 固定评测基线

保存源码/指令版本、输入身份、原始失败及实际执行记录。只按需给被测 AI 提供项目契约；评测器日志、裁判输入和评分放在被测工作目录外。

在改动前固定任务、模型、判据与成本预算。已有 eval 就复用；没有时从真实问题建立最小 eval。工具回归只证明工具范围，AI 行为必须来自真实回答和工具事件。构造场景与自然任务分别标识；真实行为的“未观察”不因离线工具测试而升级。

## 调用 HALO 诊断

使用 HALO 自己的 ChatGPT 授权，显式 `--auth-mode chatgpt`。不读取 Codex 凭据，不打印令牌，不自动改用 API Key。运行路径/账号状态/模型发现见 [运行与 trace 参考](references/runtime.md)，只在需要配置或导出时读取。

通过已加载技能目录中的 checked helper 调用；下列 `SKILL_DIR` 指本技能实际所在目录。路径均使用已核实的绝对路径。

<!-- # eval-allow: python3 -->
<!-- # eval-allow: uv -->
<!-- Python 和 uv 是 HALO 的跨项目运行依赖，不是某业务仓库的工具。 -->

```sh
python3 SKILL_DIR/scripts/diagnose.py \
  --traces /absolute/traces.jsonl \
  --prompt-file /absolute/diagnostic-question.txt \
  --output /fresh/halo-report.txt \
  --repo /absolute/harness-repo
```

安装配置提供 HALO checkout 与诊断模型；也可显式给 `--halo-repo` 和 `--model`。helper 检查非空提示、JSONL结构、运行位置和fresh输出；`--check`只做前置检查。前置失败不调用模型，运行失败保留原始输出、不自动重试。该机械检查不证明 trace 真伪、行为通过或建议有效。

向 HALO 提问可核实的问题，例如重复工具调用、具体失败后的依赖顺序、缺失的证据、版本间行为差异；要求引用 trace/span。从 overview 开始，按需 search/view_spans，避免反复读取完整大trace。启用只读源码工具后，HALO 的代码判断仍须由 Codex 核实。

## 修改、重跑和裁决

1. 将 HALO 的发现与原始记录、当前源码和项目契约对应。路径、约束和因果关系都不能仅信 HALO 的表述。
2. 建立可回退候选：记录旧身份与最小diff，不覆盖已有dirty改动。优先修复现有工具/上下文入口；避免重复AGENTS条款、整份日志塞入提示词或新增框架。
3. 用固定任务、模型和判据比较前后。裁判须为每项提供真实记录引用；回读完整答案/回执核实争议，保留原评分及纠正理由。不能在看到结果后修改判据来提高分数。
4. 分别报告正确性、耗时、token和范围。只有单样本、构造数据或成本变差时，不能宣布稳定的整体收益。预算未指定且成本明显增长时，保留候选待评，不将它默认推广为有效优化。
5. 没有通过既定门禁就回退本轮候选，保留失败trace和原因；若不再是自己应用的版本，不覆盖后续修改。通过后按已有授权保留/应用候选，再将新trace和eval送回HALO比较。

## 交付

报告实际观察、改动和未验证范围，列出前后eval/成本、保留或回退决定、产物位置及可执行回退方法。项目要求的状态记录继续遵循原项目流程。结构校验或一次高分不能代替真实任务收益；技能安装也不意味着它已在所有任务上通过行为验收。
